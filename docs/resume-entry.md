## 一、可直接粘贴的版本（推荐）

```
灵感传输终端 · 个人门户 / 社区网站
个人项目 · 独立开发 · 2026.02 – 2026.09
github.com/natsume05/inspiration-terminal ｜ 原生 PHP 8.1+ · MySQL/MariaDB · PDO · 原生 HTML/CSS/ES Modules · Docker · GitHub Actions

· 独立完成从 0 到 1 的全栈开发与上线：设计 23 张数据表承载用户、内容、互动、
  虚拟经济四个业务域，自研约 8,800 行 PHP 与 45 个路由，前端用原生 ES Module
  实现博客、社区、工具箱等模块，本地 XAMPP 调试后部署上线。

· 把数据一致性从应用层下沉到数据库层：以 25 个外键、7 个唯一键与 5 个 CHECK
  约束，使「重复点赞、重复购买、余额为负」在并发下无法发生——原先这三类问题
  依赖「先查再写」的应用逻辑，并发时必然失效；改造后由唯一键直接裁决。

· 排查并修复一处静默数据损坏：本地 MariaDB 的 sql_mode 缺少 STRICT_TRANS_TABLES，
  导致越界值被静默截断（写 -5 到 UNSIGNED 列实际存 0），连 CHECK 约束都不会触发。
  该问题在 SQLite 测试中永远不复现，只有对真实引擎跑探针才暴露；修复方式是在连接层
  强制严格模式，并把该差异写成对真实数据库的约束校验脚本纳入验收。

· 主导一次架构级重构：将 SQL、HTML 与业务逻辑混在同一文件的 34 个散落页面，重构为
  单入口前端控制器 + Repository/Service/Security/Http 分层，用静态检查工具机械化
  强制「SQL 只允许出现在仓储层」等边界；补齐 78 条单元断言与 64 条模块校验，
  并以 GitHub Actions 在 PHP 8.1/8.2/8.3 上持续验证。
```

## 三、每条改写的理由（看懂后你自己能再改）

| 我写的 | 为什么这么写 |
|---|---|
| 「个人项目 · 独立开发」（**不写"实习"**） | 仓库 17 个原始提交全是你一个人，没有公司痕迹。写"实习"会被追问"公司叫什么"，答不上来会让整份简历失信 |
| 「2026.02 – 2026.09」 | 起点有提交为证；终点含本次改造，这样才写得上"主导一次架构级重构" |
| 第 1 条讲**规模**（23 表 / 8,800 行 / 45 路由） | HR 和面试官都需要一个体量锚点。"用了什么语言"不是成就，"做了多大"才是 |
| 第 2 条讲**数据一致性**，而不是"会写增删改查" | 「会 CRUD」是最低标准等于没说。「把并发问题下沉到数据库层解决」才是设计能力 |
| 第 3 条讲**一个具体的排查过程** | 这是整份简历最独特的一条。绝大多数候选人写不出"我发现了一个只在真实数据库上才复现的问题" |
| 第 4 条讲**重构 + 质量门禁** | 证明你不只是"能写新功能"，还能读旧代码、发现隐性缺陷、建立防止回归的机制 |
| **删掉**「借助 Claude Code 掌握完整工程化实践链路」 | 原句是空话，而且主动把自己框成"AI 写的"。AI 辅助是事实，但**它是被问到再答的内容，不是简历卖点** |

## 四、投递前自查

## 五、面试时能当场展示的四样东西

这比简历上多写两行有用得多。**面试前把窗口都开好**：

| 展示什么 | 打开哪里 | 证明什么 |
|---|---|---|
| **ER 图 / 建表 SQL** | `database/migrations/001_initial_schema.sql` | 23 张表、25 个外键的真实设计 |
| **CI 绿色** | 仓库 `Actions` 标签页 | 有 78 条断言在三个 PHP 版本上真实跑过 |
| **分层边界** | `tools/lint.php` | "SQL 只允许在仓储层"是被工具强制的，不是口号 |
| **一次真实提交** | `git show 66acdee` | 门禁 bug 的完整修复过程与推理 |

> 最后一条尤其有用：**面试官几乎没见过候选人能展示"我的测试工具本身有 bug，我是这么发现的"**。这比"我写了 8,800 行代码"更能证明工程成熟度。
